RV32I pipeline: 10/10 runs on a low-cost model RV32I 管線：低成本模型 10 次全數通過

Bring AI into IC design. Let the tools be the judge. 把 AI 帶進 IC 設計，讓工具當裁判。

RTLoop helps chip teams adopt AI without trusting it blindly. In our verification loop, a low-cost model writes RTL one module at a time, and simulation, structural checks and synthesis decide what passes. Failures go back to the model as raw tool errors, within a fixed call and cost budget; if a module still fails, it stops and an engineer decides. RTLoop 協助 IC 設計團隊導入 AI，但不盲目相信 AI。在我們的驗證迴圈裡，低成本模型一次只寫一個模組，由模擬、結構檢查與合成決定能不能通過；沒通過時，原始的工具錯誤會回饋給模型，在固定的呼叫次數與費用預算內重試，仍不通過就停下，交由工程師判斷。

01How it works運作方式

A loop where the model can't grade its own work 模型無法替自己打分數的驗證迴圈

Every work package runs the same cycle. The model only proposes; the verification tools decide. A passing revision is locked and becomes a read-only dependency for the next package. The loop is model-agnostic: the same gates judge every model, and a step beyond a low-cost model, such as a bus interface, can go to a stronger one under the same gates and budgets. 每個工作包都走同樣的循環：模型只負責提案，對錯由驗證工具決定。通過的版本會被鎖定，成為後續工作包的唯讀相依模組。這個迴圈不綁定特定模型：同一套關卡評判每個模型；低成本模型做不到的步驟（例如匯流排介面），可以改用較強的模型，同樣受關卡與預算約束。

What the model sees模型會看到什麼

  • The interface spec of its module自己模組的介面規格
  • Verified dependencies, read-only已驗證、唯讀的相依模組
  • Its own previous version自己的上一版
  • Raw tool output from the last failure上次失敗的原始工具輸出
  • The repair history of this package這個工作包的修復歷史

What it can't do模型不能做什麼

  • Edit tests or other modules修改測試或其他模組
  • Declare its own success自己宣布成功
  • Exceed call or cost budgets超出呼叫次數或費用預算
  • Use latches, initial blocks or system tasks使用 latch、initial 區塊或系統任務

02Results實測結果

Measured, not promised用量測說話，不靠承諾

In every run in the table, one low-cost model wrote every module from an empty file. Our engineers wrote the interface specs, tests and decomposition plans. 表中每一次執行，每個模組都由同一個低成本模型從空白檔案寫起；介面規格、測試與拆分計畫由我們的工程師撰寫。

*SHA-256: latest round; the previous plan scored 6/10 and 9/10 in two rounds. RV32I is the base integer subset (FENCE, ECALL and CSR treated as no-ops), checked with our own testbenches rather than the official riscv-tests; memories sit outside the core. Fmax and area come from ORFS synthesis and OpenSTA before placement, with Fmax = 1000 / (clock period − worst setup slack); medians where several runs exist. Engineering estimates from September–October 2026, not signoff and not a formal model qualification. *SHA-256 為最新一輪結果，前一版計畫兩輪分別為 6/10 與 9/10。RV32I 為整數基本指令子集（FENCE、ECALL、CSR 視為 no-op），以自建測試平台驗證，並非官方 riscv-tests；記憶體在核心之外。Fmax 與面積來自 ORFS 合成與 OpenSTA、未經佈局繞線，Fmax = 1000 /（時脈週期 − 最差 setup slack）；有多次執行時取中位數。以上為 2026 年 9–10 月的工程估計值，不是 signoff，也不是正式的模型認證。

Scope today: synthesizable Verilog-2005 with a single clock, simulated with Icarus Verilog and synthesized with Yosys and OpenROAD on SkyWater SKY130. 目前範圍：單一時脈的可合成 Verilog-2005，以 Icarus Verilog 模擬，並在 SkyWater SKY130 上以 Yosys 與 OpenROAD 合成。

Why expertise matters為什麼需要專業

Decomposition decides success拆分方式決定成敗

Same pipeline spec, same low-cost model. With the whole 5-stage RV32I core in one package, most runs failed. Split into stage modules with cycle-by-cycle tests, every run passed, at about a ninth of the cost. 同一份管線規格、同一個低成本模型。整個 RV32I 5 級管線核心放在一包時，大多數執行都失敗；拆成各階段模組並配上逐週期測試後，每一次都成功，費用只有約九分之一。

What we changed我們做了哪些調整

  1. One small module per package: tens of lines, not hundreds.一個工作包只寫一個小模組，約幾十行，而不是幾百行。
  2. Large sequential blocks become one stage of logic plus its own registers, each with its own test.大型時序模組拆成「一級組合邏輯＋該級暫存器」，每一級都有自己的測試。
  3. Registers are declared on the module interface and cleared on reset, so every cycle can be compared.暫存器直接宣告在模組介面上（output reg），reset 時全部清零，測試才能逐週期比對。
  4. Tests stop at the first mismatch and print every input, actual and expected value.測試在第一個錯誤就停，並印出所有輸入、實際值與預期值。
  5. Interface specs are exact to the cycle: who updates when, reset priority, edge cases.介面規格精確到每個時脈週期：誰在哪個週期更新、reset 優先順序、邊界值。

Physical design實體設計

Beyond synthesis: RTL to GDS不只合成：從 RTL 到 GDS

We have also taken three blocks with prepared physical profiles to GDS through a fixed, hash-locked SKY130 flow. These were earlier, human-led runs: SPI's RTL is a low-cost model's refactor of reference RTL, while AES-128 and SHA-256 combined several models, with stronger ones for the bus interface and integration. RV32I and the other designs above stop at synthesis today. 我們也把三個具備實體流程設定的模組，用固定、雜湊鎖定的 SKY130 流程做到 GDS。這些是較早期、由人主導的執行：SPI 的 RTL 是低成本模型依參考 RTL 重構的版本；AES-128 與 SHA-256 混用多個模型，匯流排介面與整合使用較強的模型。上方的 RV32I 等設計目前只做到合成。

04IP & security智慧財產與資安

You control what leaves送出什麼，由您掌握

Chip teams can't afford a leaked design. Only the minimum context for one module leaves your machines, and every request is logged. IC 團隊承擔不起設計外流。除了單一模組所需的最少內容，所有資料都留在您的機器上，每筆送出的內容都有紀錄可查。

01

Verification stays local驗證在本機執行

Simulation, structural checks, synthesis and the physical flow run on your machines. Reference RTL, testbenches, netlists and layouts never leave.模擬、結構檢查、合成與實體流程都在您的機器上執行；參考 RTL、測試平台、網表與佈局都不會送出。

02

Minimum context per call每次只送必要內容

A request carries one package's interface spec, the RTL of its verified dependencies, its previous version and tool feedback. Nothing else.每次請求只帶一個工作包的介面規格、已驗證相依模組的 RTL、它的上一版與工具回饋，沒有其他內容。

03

One pinned provider指定單一供應端

Today, model calls go to one pinned provider, with fallback routing off and data collection denied.目前模型呼叫只送往指定的單一供應端，不允許備援路由，並拒絕資料收集。

04

Every call on record每次呼叫都有紀錄

Each request and response is stored with the project for audit. API keys live only in the subprocess that calls the model, never in logs, reports or Git.每次請求與回覆都和專案一起保存，可供稽核。API 金鑰只存在呼叫模型的子行程中，不會出現在紀錄、報告或 Git 裡。
